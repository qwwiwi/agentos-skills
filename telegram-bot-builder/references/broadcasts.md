# Рассылки и личные сообщения

Массовая отправка – самое опасное действие бота: отправленное не вернуть. Правила – из реальных
инцидентов. Источники – в [owner-corrections.md](owner-corrections.md).

## 1. Порядок: черновик → тест → явное «отправляй»

1. **Черновик.** Бот присылает владельцу превью ровно так, как увидят получатели (картинка, текст, кнопки), и число получателей.
2. **Тест.** Владелец смотрит превью, при необходимости – тестовая отправка себе.
3. **Явная команда.** Отправка – только после слова «отправляй» / «да, сейчас», сказанного **после** просмотра теста. «Согласую», «нравится», «супер» – это оценка дизайна, а не команда отправить. Неясно – один короткий вопрос, не отправлять.

Кнопка «Отправить» под черновиком – это и есть команда. Поэтому:

- **Черновик публикуется, только когда все кнопки и ссылки в нём уже работают на проде.** Текстовое предупреждение «не нажимай» рядом с кнопкой – не защита: владелец нажимает черновики пачкой, а бот во время длинной рассылки ставит нажатия в очередь и выполняет их позже.
- **Один черновик на адресата.** Новая версия текста – старый черновик отменить до публикации нового.

## 2. Адресаты и результат

- Явно указывай, куда идёт рассылка: личка сегмента, пост в канал, сообщение в тему чата. Значение по умолчанию у API рассылки может быть «только личка» – тогда канал молча ничего не получает. Пост в канал – отдельный вызов.
- Проверяй, что ушло, по базе (`targets`, `summary: sent/failed/blocked/total`), а не по намерению.
- `blocked` – люди, которые заблокировали бота. Это не ошибка доставки, а недостижимые адресаты.
- Повтор с тем же `broadcast_id` может ответить `ok: true` и ничего не сделать. Ответ «ok» – не доставка.
- Порядок «сначала заголовок владельцу, потом превью»: если превью упало, у владельца остаётся одинокий заголовок. Проверяй превью до заголовка или удаляй заголовок при ошибке.

## 3. Картинки в рассылке

Telegram не скачивает картинки по URL с части хостов (российские серверы): превью падает с 400,
черновик отменяется. Картинку рассылки – только по `file_id` того бота, который будет отправлять
(см. [bot-texts.md](bot-texts.md), раздел 7).

## 4. Ссылки в рассылке

- Каждая ссылка «Написать» – с `?text=` и названием кампании (см. [bot-texts.md](bot-texts.md), раздел 4).
- Куда ведёт кнопка (бот, лендинг, личка) – согласовать до создания черновика.
- UTM в ссылках: `&` в HTML-разметке экранировать как `&amp;`.

## 5. Bot API или user-аккаунт

| | Bot API (бот) | User-аккаунт (личный профиль через MTProto) |
|---|---|---|
| Первым написать человеку | нельзя, пока человек сам не нажал /start | технически можно, **но нельзя по правилам** |
| Массовые сообщения | да, тем, кто запустил бота | нет |
| Риск | блокировки бота пользователями | **бан личного аккаунта** за спам |

Правила:
- **С личного аккаунта никогда не писать первым.** Только ответ человеку, который написал сам. Первый контакт и напоминания – через бота, и только как рассылка по правилам выше.
- В личке – **не больше 2 коротких сообщений подряд**, дальше ждать ответа. Шесть сообщений за 20 минут выглядят как рассылка, а не разговор.
- Сообщения с личного аккаунта – только днём (у нас 10:00–21:00 МСК), редко. Ночью – отложить до утра.
- Публичные автоответы (комментарии) – с ротацией разных формулировок: одинаковые ответы подряд площадки считают спамом.

## 6. Тесты и боевые токены

- Тесты никогда не читают боевой `.env` (ни копией, ни симлинком). Иначе тестовый прогон шлёт настоящие сообщения настоящим людям – у нас так владелец дважды получил фальшивые «Новая оплата».
- Отправка в тестах – через мок или отдельный тестовый бот и тестовый чат.

## 7. Чек-лист рассылки

- [ ] Все кнопки и ссылки работают на проде.
- [ ] Старые черновики для того же адресата отменены.
- [ ] Адресаты указаны явно (личка / канал / чат), число получателей видно в превью.
- [ ] Картинка по `file_id`.
- [ ] Ссылки «Написать» с `?text=`.
- [ ] Владелец посмотрел тест и сказал «отправляй».
- [ ] После отправки проверены `sent/failed/blocked` в базе.
