# Тексты бота, разметка и кнопки

Правила из правок владельца по ботам практикума, AgentOS и EdgeLab Space. Источники – в
[owner-corrections.md](owner-corrections.md).

## 1. Тон и типографика

- Русский, кавычки «», тире – короткое «–» (не «—» и не «--»).
- Без «!» и без цепочек восклицательных знаков, без хайпа («бесплатно» → «вход свободный», никаких «24/7» и «доход на автопилоте»).
- Короткие строки и абзацы: 2–4 предложения, один абзац – одна мысль, **пустая строка между блоками**. Одиночный перевод строки в Telegram часто склеивает строки в один абзац.
- Все тексты бота – в одном файле (`texts.ts` / `texts.py`), с комментарием-источником у каждого шаблона.

## 2. Эмодзи

- **Не больше 1–2 эмодзи на сообщение.** В большинстве сообщений – ни одного.
- **Приветствие – один весёлый эмодзи** (например 🎉 в заголовке после оплаты). Не расставлять эмодзи перед каждой строкой.
- Эмодзи допустимы в приветствии и в напоминаниях «напишите куратору / автору». В служебных сообщениях (профиль, ошибки, статусы) – нет.
- На сайте и в мини-аппе – максимум один крупный эмодзи на экране успеха.

Пример приветствия после оплаты (подпись к баннеру, ≤ 1024 символа):

```html
<b>Добро пожаловать в практикум 🎉</b>

Оплата прошла, вы в практикуме.

Впереди 5 уроков с домашними заданиями.
Личный куратор проверит каждую домашку и подскажет.

Имя: Анна
Почта: <tg-spoiler>a***@example.com</tg-spoiler>

Первым делом напишите куратору – кнопка ниже.
```

## 3. Персональные данные в текстах

- **Почта ученика в боте – всегда под спойлером** (`<tg-spoiler>`), открывается по нажатию.
- **В черновиках сообщений куратору почты нет.** Вместо неё – имя и ID ученика (Telegram user id): «Практикум, урок 3: сдал домашку. Анна, ID 123456789». Куратор находит ученика по ID в админке. Персональные данные в личку куратора не уходят.
- Ответы бота не выдают чужие данные: на «привяжи заказ» бот не повторяет оплаченную почту целиком.
- Не пиши в сообщения пути и слова вида `secrets/`, `.env`, `token`, `password`: фильтры утечек в каналах заменяют их на `***` и ломают HTML-разметку всего сообщения.

## 4. Ссылки и кнопки «Написать»

- **Ссылка на личку – всегда с готовым текстом:** `https://t.me/<username>?text=<urlencoded>`. Голая `t.me/<username>` не допускается. Текст называет источник: «Здравствуйте! Пишу по рассылке из бота про [тему], расскажите про условия». У каждой кампании свой текст – так видно, откуда пришёл человек.
- Кнопка «Написать куратору» подставляет черновик с уроком, именем и ID (см. выше).
- Ссылки в сообщениях – обычным кликабельным текстом, **никогда внутри `<code>`**. `<code>` – только для команд и путей.
- Текст кнопки – глагол и результат: «Начать обучение», «Сдать домашку», «Написать куратору», «Ссылка для входа».
- Telegram-синий (`#2AABEE`) и самолётик – только на кнопках, которые ведут в Telegram (на сайте и в мини-аппе).
- Главная кнопка – одна. Не добавлять «мягкие» кнопки вроде «Хочу» рядом с «Оплатить и войти», если об этом не просили.

## 5. HTML parse mode: ловушки

Используй `parse_mode="HTML"` – экранирование проще, чем у MarkdownV2.

- Поддерживаются только: `<b> <i> <u> <s> <tg-spoiler> <a href> <code> <pre> <blockquote> <tg-emoji>`. Любой другой тег (`<br>`, `<p>`, `<div>`) – ошибка 400 «can't parse entities». Перевод строки – `\n`.
- **Пользовательский ввод экранировать всегда**: `&` → `&amp;`, `<` → `&lt;`, `>` → `&gt;` (`html.escape` / `escapeHtml`). Имя «Tom & Jerry» без экранирования ломает всё сообщение.
- В `href` ссылки `&` тоже экранируется: `?utm_source=x&amp;utm_medium=y`.
- Незакрытый тег = 400. Собирай разметку функциями, а не склейкой строк.

## 6. Лимиты длины

| Что | Лимит Telegram | Наша практика |
|---|---|---|
| Текст сообщения | 4096 символов после разбора разметки | держать ≤ 2000, длинное резать на «Часть 1/2» |
| Подпись к фото/видео/документу (caption) | 1024 | приветствие с баннером – целиком в 1024 |
| `callback_data` кнопки | 1–64 байта | короткие ключи, данные – в базе |
| Скорость отправки (FAQ Telegram, ориентир) | ~30 сообщений в секунду в разные чаты, ~1 в секунду в один чат, ~20 в минуту в группу | очередь с паузами, на 429 ждать `retry_after` |

Длинные HTML-сообщения иногда «отправлены», но не доходят. Ответ API «ok» – не доказательство доставки
длинного сообщения; для важных текстов режь на части.

## 7. Картинки: file_id вместо URL

- Telegram скачивает картинку по URL сам, и с части хостов (российские серверы) не может: `sendPhoto` → 400 «failed to get HTTP URL content». Проверка `curl` со своей машины ничего не доказывает.
- Решение: один раз загрузить файл боту (multipart `sendPhoto` себе в личку с `disable_notification`), взять `file_id` самого большого размера, сообщение удалить, дальше слать по `file_id`.
- `file_id` привязан к боту: для другого бота – получить заново.
- Баннеры приветствия – 1536×1024 или близко, текст набран вёрсткой, а не нарисован моделью.

## 8. Меню команд

- `setMyCommands` разрешается по самому узкому scope: chat → chat_member → all_private_chats → default. Если когда-то записали команды в `all_private_chats`, обновление `default` в личке не видно. Лечится `deleteMyCommands` для старого scope.
- Служебные команды владельца – в scope его чата (`BotCommandScopeChat`), не в `default`.
- Меню обновляется в коде при старте бота, а не руками. Клиент Telegram кэширует меню – переоткрыть чат.

## 9. Чек-лист текстов

- [ ] Тире «–», кавычки «», без «!».
- [ ] Пустая строка между блоками, абзацы короткие.
- [ ] Эмодзи: 0 в служебных, 1 в приветствии, максимум 1–2 в сообщении.
- [ ] Почта – под спойлером; в черновиках куратору – имя и ID, без почты.
- [ ] Каждая ссылка «Написать» – с `?text=` и источником.
- [ ] Ссылки кликабельные, не в `<code>`.
- [ ] Пользовательский ввод экранирован, теги только из списка Telegram.
- [ ] Сообщение ≤ 2000, подпись ≤ 1024.
- [ ] Картинки по `file_id`.
