# Правила и откуда они взялись

Каждое правило скилла – с источником и причиной. Источники: внутренние заметки команды,
дизайн-система и история наших проектов, опубликованный урок «Стек вайбкодера»
(EdgeLab Space, 15.06.2026). Персональных данных, адресов серверов и токенов здесь нет намеренно.

| Правило | Источник | Почему |
|---|---|---|
| Реестр скиллов – skills.sh, установка Supabase-скилла `npx skills add supabase/agent-skills` | внутренняя заметка команды; проверено в npm 04.11.2026 (пакет `skills` 1.7.6) | skill.sh – припаркованный домен, ссылка вела в никуда |
| Команды `claude skill add` нет, установка – `git clone` + `cp` в `~/.claude/skills/` | внутренняя заметка команды | команда была в README этого репозитория и не работала у студентов |
| Две оси выбора стека, Яндекс и CSR, четыре формата | урок «Стек вайбкодера» (разделы 00–04, 08) | исходная структура урока, одобрена владельцем |
| 152-ФЗ: сначала «чьи данные», потом сервер | урок, раздел 06 | закон о персональных данных |
| Данные из Telegram не выносим на российские серверы | внутренняя заметка команды (решение владельца 18.10.2026) | риск юрисдикции для данных пользователей Telegram |
| Лендинг начинать с простого: статический HTML, Astro – когда страниц больше | внутренний документ (сайт без шага сборки); внутренняя заметка команды (переписать лендинг на Astro + Tailwind) | лендинг продавал с первого дня без фреймворка |
| Кабинет – Next.js App Router `standalone` на self-host Supabase | внутренняя заметка команды; внутренний документ нашего кабинета (Next.js 16) | так собраны оба наших кабинета; в брифе было «React/Vite» – по источникам это Next.js |
| Деплой только из чистого коммита на `origin`, стадия из `git archive` | внутренний документ, раздел Deploy; заметка о партнёрском статичном лендинге (выкладка `git archive` + rsync) | на сервер не попадает незакоммиченное и непроверенное |
| Релизы + симлинк `current`, проверка по `/proc/PID/cwd` | внутренняя заметка команды | grep по старой плоской папке дал ложный вывод «фикс не задеплоен» |
| Прод – только по явному «да», после выката – Playwright по живому сайту | внутренняя заметка команды (указание владельца 15.07.2026); правила владельца для агентов | `curl` доказывает только доставку файла, не работу экрана |
| Зеркало получает каждый деплой | внутренняя заметка команды | иначе адреса расходятся |
| CI не используем: `scripts/check.sh` + `.githooks/pre-push`, вывод в PR | правила владельца для агентов (решение 12.10.2026); `scripts/check.sh` в нашем проекте | проверки локально, без GitHub Actions |
| Приоритет интеграционным тестам на бэкенде, e2e – только критичное | правила владельца для агентов | дорогие тесты, которые мало ловят, – удалять |
| Секреты только в `.env`, не в чате и не в репозитории | правила владельца для агентов; внутренний документ (запись о публичном репозитории с именами и путями) | чат с агентом видят другие; публичный репозиторий пришлось чистить |
| Логи бота – только через фильтр токена | внутренняя заметка команды | HTTP-клиент пишет полный URL с токеном |

| Платежи – простое правило без состояния | внутренняя заметка команды (владелец, 23.09.2026) | таймер у ссылки на оплату дважды не прошёл ревью и был удалён |
