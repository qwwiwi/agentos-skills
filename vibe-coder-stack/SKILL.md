# Стек вайбкодера: на чём собрать любой проект

Скилл для новичка, который строит проект вместе с AI-агентом. Задача агента –
не устроить обзор всех технологий, а за 5 минут привести человека к одному стеку,
одному стартовому репозиторию и первому промпту.

Порядок работы всегда один:

1. **Архетип.** Определи, что строим (таблица ниже). Если непонятно – задай два вопроса из раздела «Две оси».
2. **Стек.** Возьми стек архетипа без вариаций. Отклоняйся, только если человек назвал причину.
3. **Стартовый репозиторий.** Дай ссылку и команду клонирования из [references/archetypes.md](references/archetypes.md).
4. **Промпты по шагам.** Выдай готовые промпты из того же файла: каркас → данные → дизайн → деплой.
5. **Ловушки.** До первого деплоя пройди [references/deploy-and-ops.md](references/deploy-and-ops.md) и [references/design-rules.md](references/design-rules.md).

## Две оси выбора

Стек выбирают не по моде, а по двум вопросам.

**Ось 1 – видит ли контент поисковик?**
- Публичное (лендинг, статьи, карточки) → готовый HTML: SSG (статика при сборке) или SSR.
- За логином (кабинет) → индексировать нечего → CSR или SSR без требований к SEO.
- Яндекс рендерит JS хуже Google: для публичных страниц чистый CSR – табу.

**Ось 2 – код пишет агент.**
Агенту нужны рельсы: TypeScript, схемы (Zod), популярный инструмент с большим корпусом
примеров. Тогда агент ошибается реже, а компилятор ловит баги до прода.

## Архетип → стек

| Архетип | Рендер | Стек | Данные | Пример у нас |
|---|---|---|---|---|
| Продающий лендинг | SSG | Astro + Tailwind или чистый HTML + CSS | – | лендинг практикума (сначала статический HTML, затем Astro + Tailwind); статичный лендинг партнёрского проекта |
| SEO-портал / блог | SSG | Astro (+ Starlight для документации) | markdown в репозитории | – |
| Платформа с личным кабинетом | SSR/CSR | Next.js (App Router, `output: 'standalone'`) или React + Vite | self-host Supabase (Postgres + Auth + RLS) | кабинет AgentOS, платформа EdgeLab Space |
| Telegram-бот | – | TypeScript + grammY или Python + aiogram 3 | Postgres / Supabase | боты сообщества и практикума |
| Telegram Mini App | CSR внутри Telegram | тот же фронт кабинета + Telegram SDK, вход по initData | тот же бэкенд | мини-апп кабинета практикума и AgentOS |

Правило выбора между Next.js и React + Vite: если в кабинете есть публичные страницы
(тарифы, «о продукте») или нужен серверный рендер – Next.js. Если всё за логином и нужен
максимально простой фронт – React + Vite. Не смешивать оба в одном проекте.

Mini App – не отдельный проект. Это та же сборка кабинета, открытая внутри Telegram,
со своим входом и своими правилами экрана. Детали Mini App – в скилле `telegram-bot-builder`
(`references/mini-apps.md`).

## Что мы выкатили и что сработало

Короткая выжимка, подробности и источники – в [references/owner-corrections.md](references/owner-corrections.md).

- **Простое сначала.** Лендинг практикума вышел статическим HTML без сборки и продавал с первого дня; на Astro его перевели, когда страниц стало больше. Не начинай лендинг с тяжёлого фреймворка.
- **Деплой только из git.** Скрипт деплоя отказывается работать с грязным деревом и с коммитом, которого нет на `origin`, и собирает стадию из коммита (`git archive`), а не из рабочей папки.
- **Staging → prod.** Сначала стенд, потом прод, и только по явному «да, на прод». После выката – проверка живого сайта в браузере (Playwright, телефон и десктоп), а не только `curl`.
- **CI не нужен.** Проверки – локально: `scripts/check.sh` (типы, линт, тесты, сборка) и git-хук `pre-push`, который его запускает. Вывод `check.sh` – в описание PR.
- **Секреты только в `.env`.** Не в чате с агентом, не в репозитории, не в логах. В публичных репозиториях – ни имён серверов, ни IP, ни ID.
- **152-ФЗ.** Сначала вопрос «чьи это данные», потом выбор сервера. Персональные данные граждан РФ – на российском сервере.
- **Российский хостинг и Telegram не дружат.** С российского сервера часто не достучаться до `api.telegram.org`, а Telegram не может скачать картинку по URL с российского хоста. Бот – на зарубежном сервере, картинки – через `file_id`.

## Скиллы-ускорители и установка

Команды проверены: реестр называется **skills.sh** (с «s»), команды `claude skill add` в Claude Code нет.

```bash
# senior-brainstorm и telegram-bot-builder, vibe-coder-stack – из этого репозитория
git clone https://github.com/qwwiwi/agentos-skills.git
cp -r agentos-skills/vibe-coder-stack     ~/.claude/skills/
cp -r agentos-skills/senior-brainstorm    ~/.claude/skills/
cp -r agentos-skills/telegram-bot-builder ~/.claude/skills/

# Superpowers – методология: план, тесты, субагенты (внутри Claude Code)
/plugin install superpowers@claude-plugins-official

# Официальный скилл Supabase – из реестра skills.sh
npx skills add supabase/agent-skills
```

После копирования перезапусти Claude Code – скиллы появятся в списке.

## Чек-лист перед первым деплоем

- [ ] Архетип и стек названы одной строкой, без «или».
- [ ] Репозиторий на GitHub, ветка `main` защищена, работа в ветках `feature/…`.
- [ ] `scripts/check.sh` проходит локально, `pre-push` его запускает.
- [ ] `.env` в `.gitignore`, в репозитории только `.env.example` без значений.
- [ ] Сервер выбран по вопросу «чьи данные» (152-ФЗ).
- [ ] Есть стенд, деплой на прод – отдельной командой.
- [ ] После деплоя открыт живой сайт на 390 px и 1440 px, скриншоты сделаны.
